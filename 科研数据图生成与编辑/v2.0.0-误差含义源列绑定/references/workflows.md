# Source extraction, source-preserving editing and publication QA

## Extract scientific meaning before plotting

Read actual table values and original paper figure/caption together. Build a compact requirement table: requested figure/panel → chart type → source table/sheet/columns/row keys → units/scale → labels/errors → style/export → requested change. Resolve differences from primary source; document unresolved conflicts and confidence. Do not extrapolate biology from labels or assume a figure's interpretation from its number.

For PDFs use `pdftotext -layout`, PyMuPDF or pdfplumber; inspect actual pages to confirm multi-column order, captions, minus signs, superscripts, table boundaries and OCR decimal points. Render relevant pages at readable scale and compare with final panel. If table extracted programmatically is messy, preserve original page/cell anchors and create a validated tidy derivative. Never use random or made-up values to stand in for extraction. Raster digitization is last resort with explicit calibration, error bounds and approximate status; prefer supplied numerical source.

Data record example structure (not case content): source version/hash; source sheet/table/page; original row ID; source column; original value/unit; transform formula; display value; plotted coordinate; semantic element/group ID; uncertainty. Use both forward and reverse index. Save `plot_spec.json`, source version list, run script, installed tool versions and exact rerun command. Avoid copying large original data unless required; if retained only by absolute input path, explain dependency and preserve original SHA256. Prefer a self-contained project with necessary small source subsets and original row mapping when permitted.

## Edit existing sources, do not silently redraw

1. Copy original to versioned read-only backup; record SHA256 and render it before edits. Inventory original native objects, IDs, groups, text, transforms, axes and associated table/code. Check for linked images/fonts and preserve their paths.
2. Write explicit change plan: requested edits, target IDs/source variables, expected before→after; invariants include unchanged numerical values, series identity, panel order, unrequested shapes and scientific assertions. For a value change, require a source correction and update provenance; for style-only edits, source values and geometry must remain scientifically equivalent.
3. For supplied Python/R/plot project, change parameters in the original generator and rerun against original data. Preserve project/code lineage and record a diff, not a fresh generic generator. If only SVG source exists use `diagram.py patch` or targeted XML edits on that source, retaining IDs/layers/transforms. SVG CSS may override presentation attributes: inspect effective styles and edit at the correct level. ElementTree may reserialize namespaces; preserve semantic subtrees rather than falsely claim byte-identical XML.
4. Source SVG positions may be in nested transforms or logarithmic axes. Do not hand-adjust bar heights/point positions based on viewport guesses. Trace back to data/axes and apply consistent transformation; if impossible, state limit. Do not change a series color without updating its legend key. Preserve labels as `<text>`/`<tspan>`.
5. Native Office editing: inspect XML and embedded data. Use native shape/chart APIs where installed; retain slide/page dimensions, ordering, chart data, object relationships and document properties. PPTX source must contain individually editable objects/charts/text, not one raster screenshot. Save actual `.pptx`; render through LibreOffice/available renderer into PDF and PNG. If the native app is unavailable, export what is genuinely possible and mark required native editing incomplete.
6. Compare before/after renders and actual source data. Verify retained IDs and subtree invariants where relevant, source hashes and intended changes; add `changes.json` with code diff/ID-level before-after and explanation. A new SVG embedded into the old document is not proof of source-preserving editing.

## Scientific schematics when requested

Build a source-supported entity/relationship table first: exact entity label, biological level (gene/protein/species/compound), compartment/space, direction/sign, evidence location and uncertainty. Read primary source captions/passages and compare original figure. Avoid merging distinct molecules, converting association into causation, reversing inhibition, or confusing translation/translocation with activation. Explicit scientific validation remains required even when quotes are present.

Optional `diagram.py render --spec /app/work/diagram_spec.json --out /app/output/figure.svg` supports: `width,height` in viewBox units; optional `width_mm,height_mm,font_family,font_size`; `nodes` with unique `id,label,x,y,w,h`; `groups` with `id,label,x,y,w,h`; `edges` with unique `id,source,target,kind` (`activation,inhibition,association,sequence,arrow`), optional `points`, `label,label_x,label_y,dashed`; `legend` list `{label,color,x?,y?}`. Edges terminate at node boundaries; inhibition marker is at target. Rectangular nodes are generic geometry only; organelles, membranes, complexes, feedback, branched pathways, self-loops, binding, transport, precise compartment boundaries require custom/native shapes and correct topology. Use explicit bends/routing; do not force biology into generic boxes if shape/spatial meaning matters. Export actual SVG/PNG/PDF and attach source map and scientific review; helper cannot decide science.

## Fonts, styles and export

- Probe font files and coverage with `fc-list`, `fc-match :lang=zh`, or Matplotlib font_manager. For CJK prefer an actually installed suitable Noto/Source Han/WenQuanYi font. Test all actual characters using fontTools cmap or actual rendering; catch `Glyph ... missing` warnings. A fallback family name without an installed file is not a fix. For math text, preserve editable scientific typography or use native text with Unicode and separate superscript spans. Inspect negative signs, µ vs u, multiplication × and ±.
- Default helpers use an original restrained colorblind-friendly palette and fixed journal-scale dimensions; these are reusable defaults, not a named journal template. A case's exact style sheet wins. Record default decisions when constraints absent. Use one series registry across panels, distinguish lines by markers/dashes when grayscale required. Ensure actual print-size text is legible; long labels may need wrapping, rotation or additional height, not tiny fonts. Align axes/panels and use the requested panel letters; keep units and legend away from data/error bars.
- SVG: real XML paths/native text, stable IDs/group layers, correct viewBox and physical dimensions; linked assets present and properly referenced. Raster heatmap backgrounds may violate fully vector requirements; helper uses vector cells. Inspect that the source remains semantically editable.
- PNG: actual signature, reopen with Pillow, size approximately `width_mm/25.4*dpi` by `height_mm/25.4*dpi`, check DPI metadata, requested mode/transparency. Do not upscale a low-resolution raster and claim new scientific resolution. Use physical size, not just a large pixel count.
- PDF: `%PDF-`, render/open, `pdfinfo` page size, `pdffonts` embedding/subsetting, inspect selectable text. RGB SVG/Matplotlib output is not CMYK. For explicitly requested CMYK/profile use available proper color-managed export (e.g. Ghostscript with supplied profile), preserve original editable RGB source and inspect separation/color metadata. Never label an RGB file CMYK without conversion. If not possible, record failure, not silent compliance.
- Fixed size exports must not use `bbox_inches='tight'`, which changes page/pixel dimensions. Fix layout within the specified canvas instead. Record real margins and DPI; use no outer decorations unrelated to the workorder.

## Verification and bounded repair

First automatic pass: reread source and verify file hashes/cells and artist values, check group/legend identity and source coverage, text existence, file formats/size/DPI. When `label_column` and `color_column` are set, `check_legend_series.py` must exit 0: SVG legend text and swatch equal the selected table pair. `verify_sources.py` independently reloads each referenced table, detects changed inputs and missing row/column locators, reconstructs reverse row/field index and checks direct mark geometry. It does not validate custom transformed provenance without an adapter, nor scientific meaning.

Then visual/scientific pass: inspect PNG and actual PDF render side-by-side with original; enumerate mismatches in `/app/output/validation.json` with source locator, severity, action and actual recheck outcome. Inspect collision-prone title/tick/legend/error/significance/panel labels; automatic bounds checks miss many collisions. For extremely dense panels use source-aware label selection, inset or the specified layout; do not delete inconvenient values. Fix substantial errors and rerun once or twice as time allows. Preserve useful partial outputs if blocked. Distinguish machine `passed` checks, Agent visual/scientific review and human approval; never interchange them.

For relative improvement provide the observable capabilities (source map, invariant checks, actual revision count/time and errors repaired); platform supplies baseline comparisons. No self-awarded gain percentages, synthetic benchmark scores, fake human signoff or claims of official case performance.
