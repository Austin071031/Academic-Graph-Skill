# Source-bound scientific charts — 1.6.0

Produce the actual requested figures and editable project, not merely analysis or plotting code. Derive every scientific value, label and relationship from the current inputs. No fixed case answers exist in this skill. A domain label or filename is not scientific evidence. Do not fabricate numerical values, statistics, scientific relationships, human approval, software state, or comparison scores.

## Installation and startup boundary

The ARM authoring entrypoint stages these reusable resources at `/app/submission` using only the Python standard library. It must not run examples or depend on Matplotlib, fonts, Cairo, JSON Schema or native Office software to install the skill. The platform then installs `/app/submission` under `/skills/weekly-skill`; scientific plotting happens only when the platform invokes that installed skill on its actual input. Examples and authoring checks are opt-in and must never replace this installation step.

## Runtime workflow

1. **Read first:** `/input/case.json`, actual `task.md`, and `environment/resources.yaml` (locate the latter two). Read the full original `output_contract`, required filenames/formats, edit instructions and supplied materials. Installed helpers are under `/skills/weekly-skill/scripts/`; do not assume current directory. Work in `/app/work`, deliver in `/app/output`.
2. Inventory actual attachments with `python3 /skills/weekly-skill/scripts/diagram.py inspect --input /input --out /app/work/inventory.json`. Read tables, notes, original figure, style guide, captions and paper pages. Use PDF text extraction and rendered pages; OCR only when necessary. For biological content use primary source passages/figure captions, not prior knowledge alone. Actual paper/source data override misleading domain labels. Read [references/workflows.md](references/workflows.md) before extracting or editing scientific content.
3. Create an honest partial `/app/output/result.json` early: original `case_id`, **all original output_contract fields with original names and types**, actual status, unresolved work. If schema is provided, follow nested shape and enums. Do not put dummy paths or claim success. Then produce a useful first figure; reserve at least the final third of budget for checking, correction and delivery. Budget: 64 requests, 900 s. Prefer batched input inspection and deterministic plotting; do not spend the budget installing unnecessary tools or building a baseline (platform handles comparisons).
4. Choose **generation vs source-preserving edit**. For an edit, start from the supplied SVG/native project/script; preserve original, unchanged data, objects, IDs, layers and scientific meaning. A redrawn lookalike is not a preserved source. See the edit workflow. Create reusable `plot_spec.json` or equivalent style config plus executable plotting project. Record source SHA256, sheet/page/row/column, conversions, filtering, category order, error meaning, and explicit uncertainties. Use native source data, not a screenshot, whenever provided.
5. **Render now.** For table-driven bar/line/scatter/box/heatmap/pie charts, use `charts.py inspect` and `charts.py render` as described in [references/interfaces.md](references/interfaces.md). When the source table names the series and its swatch, set both `label_column` and `color_column` on that series. Render then uses the single label and color in the selected rows for the marks and the legend, and rejects a blank cell or more than one pair. A spec `label` or `color` that disagrees with the table is not used. After render, run `python3 /skills/weekly-skill/scripts/check_legend_series.py --spec /app/output/plot_spec.json --svg /app/output/<name>.svg`. Exit 0 means each legend entry matches the table. Exit 1 means it does not; do not claim the legend is correct. For a significance mark stored in a table cell, set the annotation `source` to the table id, plus `text_column` and logical `row`. Render draws that cell and ignores a conflicting `text`. After render, run `python3 /skills/weekly-skill/scripts/check_significance.py --spec /app/output/plot_spec.json --svg /app/output/<name>.svg`. Exit 0 means the cell text is visible. Exit 1 means it is not. It reads actual source cells, produces SVG with native text and stable IDs, PNG/PDF, source_map and actual geometry/export checks. Do not bend a complex case to fit the helper: adapt a copy under `/app/output` or write a case-specific Matplotlib script using the same provenance and validation conventions. For schematics, use explicit geometry/native source editing; the optional diagram helper supports entities, compartments and directed/inhibitory edges. Read the schematic section in workflows only if applicable.
6. **Inspect and repair.** Open the real PNG and rendered PDF pages. Check every requested panel against original source values/captions and the original figure if available. Verify six classes: scientific entities; spatial/arrow relations; data encoding; axes/legends/annotations; editable source; export formats. Check exact spelling, axis scale/unit multipliers, category and legend order/colors, error meaning and lengths, supplied significance, n and panel labels. Do not create statistical tests or choose their validity; reproduce supplied results only. Missing significance/n is explicitly recorded. Never add p-values or stars inferred from bar height.
7. **Finalize and verify:** deliver all requested artifacts, actual source/provenance/edit records and measured export checks. Reopen files, validate result against original contract, preserve original case_id. First write `/app/work/delivery_manifest.json` listing the ACTUAL required artifact paths/formats/physical constraints read from the workorder; run `python3 /skills/weekly-skill/scripts/validate_delivery.py --root /app/output --manifest /app/work/delivery_manifest.json --out /app/output/delivery_checks.json`. Run `verify_sources.py` for helper-generated maps. Missing files or failed checks prohibit claiming complete delivery; `needs_review` is not a pass. Then finalize. Schema validity alone does not prove artifact existence. `diagram.py finalize --case /input/case.json --report /app/work/final_report.json --out /app/output/result.json` validates common contract forms and atomically writes; it does not fill scientific content. For unsupported contracts, implement their actual schema explicitly. Do not rename Chinese keys into English or bury required top-level fields under a generic wrapper. A final chat response does not replace saved result.json.

## Data correctness invariants

- Preserve source table and row identity through filtering/sorting/joins. Distinguish data from formatted display; do not round data before plotting. Never align groups by accidental row order. Align by documented keys, reject ambiguous duplicates.
- Explicitly inspect encoding, delimiter, sheet, header rows, units, percentages, decimal separators, missing tokens and formulas. XLSX cached formula values may be absent/stale: inspect formulas; do not pretend a missing cache is zero. Legacy XLS/irregular sheets require a proper reader/custom preprocessing.
- Errors are distances, not endpoints. For supplied CI endpoints, derive lower=`estimate-low`, upper=`high-estimate`, retaining original columns and formula. Do not confuse SD and SEM. Replicate aggregation is allowed only when the workorder/source defines the method; retain all contributing row IDs, n and degrees-of-freedom convention. No arbitrary deduplication, interpolation, normalization, outlier removal or imputation.
- Linear vs logarithmic scale, reference/baseline, axis breaks and zero matter. Bars normally include zero; do not silently truncate. Nonpositive log values are reported and handled explicitly. Missing line values break lines; never connect across dropped gaps without disclosure. Sorting only when scientifically justified (time/concentration), retaining original row IDs.
- Scientific symbols, Greek letters, superscripts, negative signs and CJK text must render. Probe installed font coverage and choose a real installed font. Preserve editable SVG `<text>` with `svg.fonttype=none`; PDF TrueType embedding via `pdf.fonttype=42`. Do not solve missing fonts by converting all source text to outlines. See font/export instructions in workflows.
- Reusable style settings must record physical width/height, font family/size, palette and series registry, line width, panel grid, margins, DPI, background, color mode. Explicit journal requirements override defaults; never invent a journal specification. Preserve series-to-color identity across panels/edits.

## Required runtime deliverables

Follow each actual contract; the following are supplements, not replacement field names:

- Real editable SVG plus any specifically requested native file (PPTX, AI-compatible vector, Office chart, etc.), actual PNG and PDF; runnable plotting script and configuration with source paths/versions. A screenshot embedded in SVG/PPTX is not an editable chart. SVG cannot substitute for a requested PPTX.
- `source_map.json`: element/group ID → source path+SHA256, sheet/page/figure/table locator, logical row and column, exact raw values/passages, transformations, series identity and version. Reverse lookup from source row/field to element ID; grouped elements use group ID plus point/cell index. Give direct source locators, not simply a bibliography. Attach annotation and relationship sources, including uncertainty.
- `changes.json`: original/new SHA256, actual requested edits, retained/changed element IDs or source code diffs, before/after values and style, reason/source, version. Human confirmation is `not_performed` unless actually supplied.
- `export_checks.json`: measured size/DPI/pixel dimensions/file signatures, font and color findings, geometry/source checks, visual inspection outcomes and exceptions. Report actual tool errors. Do not treat text presence or valid PDF signature as proof of scientific correctness.
- Runtime outcome/status distinguishes **missing materials**, **cannot determine scientific content**, and **execution/export failure**. Retain useful artifacts under partial status. Preserve all required original fields even if their content must honestly describe an unavailable result. Only declare completed when requested artifacts actually exist and substantive checks pass.

## Dependencies and boundaries

Python 3.9+ recommended. `charts.py inspect`: stdlib CSV/TSV/JSON; XLSX adds openpyxl. `render`: matplotlib>=3.5, numpy>=1.21, Pillow>=9; install only missing packages into available runtime if permitted. Optional jsonschema validates full schema. Diagram core uses stdlib; export uses available Inkscape, librsvg or CairoSVG + system Cairo. Probe supplied environment first. Do not rely on author-local paths, remote services, paid assets or API credentials. Helpers and style defaults are original reusable resources; fonts are selected from the execution environment and must retain their license/source information if copied.

Static helpers cannot establish biological causality or recover nonexistent data. Source-aware Agent judgement and visual review remain necessary. Generic image generation is unsuitable for quantitative charts. If only a raster original is available, label any reconstruction/digitization as approximate, retain original image and method, and do not claim precise source-preserving editing.
